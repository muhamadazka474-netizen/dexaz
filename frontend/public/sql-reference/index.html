MODULE 01

SELECT // BASICS

Memahami cara mengambil data, memilih kolom, dan membangun query SELECT dari dasar.

Q-01SELECT / FROMBEGINNER
SELECT nama, email
FROM pelanggan;

SELECT menentukan kolom yang ingin ditampilkan; FROM menentukan sumber tabel.

✓ Tidak mengubah data✓ Dasar laporan✓ Bisa memilih kolom tertentu

FUNGSI / TUJUAN

Mengambil kolom tertentu dari satu tabel tanpa mengubah data.

CARA MENGGUNAKAN

Gunakan SELECT setelah menentukan tabel pada FROM. Pilih hanya kolom yang diperlukan; gunakan * hanya ketika memang membutuhkan semua kolom.

SELECT nama, email FROM pelanggan;

CONTOH LEBIH LENGKAP

Kolom yang dipilih tidak harus sesuai urutan pada tabel — tambahkan kolom lain sesuai kebutuhan laporan.

SELECT id, nama, kota FROM pelanggan;

KEGUNAAN / USE CASE

Untuk menampilkan data, membuat laporan, memeriksa isi tabel, dan menjadi dasar query JOIN, filter, agregasi, atau subquery.

CARA KERJA

SELECT memilih data/ekspresi yang ditampilkan. FROM menentukan sumber data. Koma memisahkan beberapa kolom. ; mengakhiri statement.

CATATAN & ERROR UMUM

Hindari SELECT * pada laporan produksi karena mengambil kolom yang tidak diperlukan dan membuat hasil kurang stabil ketika struktur tabel berubah.

Q-02SELECT DISTINCTBEGINNER
SELECT DISTINCT kota
FROM pelanggan;

Menghilangkan baris duplikat berdasarkan kolom/ekspresi yang dipilih.

MANFAAT
Mencari daftar nilai unik, misalnya seluruh kota pelanggan.

FUNGSI / TUJUAN

Menghasilkan nilai unik dan menghilangkan duplikasi dari hasil query.

CARA MENGGUNAKAN

Letakkan DISTINCT tepat setelah SELECT. Semua kolom yang dipilih dipertimbangkan bersama; DISTINCT nama, kota berarti kombinasi nama+kota harus unik.

SELECT DISTINCT kota FROM pelanggan;

KEGUNAAN / USE CASE

Membuat daftar referensi unik, memeriksa kategori yang tersedia, dan membersihkan duplikasi pada hasil laporan.

CARA KERJA

DISTINCT bekerja pada hasil SELECT. Jika dua baris memiliki nilai berbeda pada salah satu kolom yang dipilih, keduanya tetap muncul.

CATATAN & ERROR UMUM

DISTINCT dapat membutuhkan sorting/hash sehingga pada data besar jangan digunakan tanpa alasan.

Q-03WHERE / AND / ORBEGINNER
SELECT *
FROM pelanggan
WHERE kota = 'Jakarta'
  AND status = 'AKTIF';

WHERE menyaring baris. Gabungkan kondisi dengan AND/OR/NOT.

ERROR UMUM: menggunakan = NULL. Gunakan IS NULL.

FUNGSI / TUJUAN

Menyaring baris berdasarkan kondisi logika sebelum hasil dikembalikan.

CARA MENGGUNAKAN

Tulis kondisi setelah WHERE. Gunakan AND untuk semua kondisi wajib terpenuhi, OR untuk salah satu kondisi, dan tanda kurung ketika mencampur AND dan OR agar logika jelas.

SELECT * FROM pelanggan WHERE kota = 'Jakarta' AND status = 'AKTIF';

KEGUNAAN / USE CASE

Mengambil data sesuai kriteria, pencarian pelanggan tertentu, validasi data, dan membatasi data yang diproses query lanjutan.

CARA KERJA

WHERE memfilter baris. Operator perbandingan seperti =, >, < dan operator logika AND/OR/NOT menentukan kondisi.

CATATAN & ERROR UMUM

Kesalahan umum adalah lupa WHERE pada UPDATE/DELETE atau menggunakan = NULL. NULL harus diuji dengan IS NULL/IS NOT NULL.

Q-04LIKE / IN / BETWEENBEGINNER
SELECT * FROM produk
WHERE nama LIKE '%Laptop%'
   OR kategori IN ('IT','Office');

LIKE untuk pola teks, IN untuk beberapa nilai, BETWEEN untuk rentang.

FUNGSI / TUJUAN

Mencari data berdasarkan pola teks, daftar nilai, atau rentang.

CARA MENGGUNAKAN

LIKE memakai % untuk nol atau banyak karakter dan _ untuk satu karakter. IN menerima daftar nilai. BETWEEN digunakan untuk rentang dan umumnya bersifat inklusif pada batas.

SELECT * FROM produk WHERE nama LIKE '%Laptop%' OR kategori IN ('IT','Office');

KEGUNAAN / USE CASE

Pencarian nama, filter kategori, rentang harga/tanggal, dan penyederhanaan banyak kondisi OR.

CARA KERJA

LIKE = pola teks; IN = salah satu dari daftar; BETWEEN = berada di antara dua nilai. Gunakan NOT untuk membalik kondisi.

CATATAN & ERROR UMUM

LIKE dengan wildcard di awal (%Laptop%) sering tidak dapat memanfaatkan index biasa secara optimal. Perhatikan juga aturan case sensitivity tiap DBMS.

MODULE 02

ORDER // LIMIT

Mengatur urutan hasil, memilih data teratas, dan melakukan pagination. Modul ini menjelaskan bagaimana SQL menentukan urutan hasil dan bagaimana membatasi baris secara aman.

Q-03ORDER BYBEGINNER
SELECT nama, total, tanggal
FROM transaksi
ORDER BY total DESC, nama ASC;

Mengurutkan baris hasil query berdasarkan satu atau beberapa kolom.

FUNGSI / TUJUAN

ORDER BY digunakan ketika hasil query perlu disajikan dalam urutan tertentu. Tanpa ORDER BY, database tidak menjamin urutan baris yang dikembalikan. Anda dapat mengurutkan angka dari terbesar ke terkecil, teks secara alfabetis, atau tanggal dari terbaru ke terlama.

CARA MEMAKAI

Tulis ORDER BY setelah SELECT/FROM/WHERE/GROUP BY/HAVING. Tambahkan nama kolom atau ekspresi yang ingin diurutkan. Gunakan ASC untuk naik dan DESC untuk turun. Jika ada lebih dari satu kolom, kolom kedua menjadi aturan tie-breaker.

SELECT nama, total
FROM transaksi
WHERE status = 'LUNAS'
ORDER BY total DESC, nama ASC;

CONTOH PENGGUNAAN LENGKAP

Misalnya ingin membuat laporan 10 transaksi terbesar. Gunakan ORDER BY untuk menentukan peringkat berdasarkan nilai transaksi, lalu LIMIT untuk mengambil 10 baris pertama.

SELECT id, nama, total, tanggal
FROM transaksi
WHERE tanggal >= '2026-01-01'
ORDER BY total DESC, tanggal DESC;

KEGUNAAN / MANFAAT

Digunakan untuk laporan penjualan, daftar pelanggan, ranking nilai, transaksi terbaru, daftar prioritas, monitoring operasional, dan penyajian data yang mudah dibaca manusia.

CARA KERJA

Database terlebih dahulu menghasilkan kumpulan baris dari FROM/JOIN dan menyaringnya melalui WHERE. Setelah agregasi dan HAVING bila ada, ORDER BY menentukan urutan akhir hasil. Karena proses sorting dapat mahal pada dataset besar, pertimbangkan index dan LIMIT bila hanya membutuhkan sebagian hasil.

VARIASI PENTING

-- Terbaru ke terlama
ORDER BY tanggal DESC;

-- Alfabetis
ORDER BY nama ASC;

-- Berdasarkan hasil perhitungan
ORDER BY total * jumlah DESC;

CATATAN & ERROR UMUM

Jangan mengandalkan urutan alami tabel. Perhatikan NULL, collation/case sensitivity, dan penggunaan ekspresi. Untuk hasil yang konsisten saat nilai sama, tambahkan tie-breaker seperti id.

Q-04LIMIT / OFFSETINTERMEDIATE
SELECT id, nama, total
FROM transaksi
ORDER BY tanggal DESC
LIMIT 20 OFFSET 40;

Membatasi jumlah baris dan melewati sejumlah baris untuk kebutuhan pagination atau preview data.

FUNGSI / TUJUAN

LIMIT membatasi berapa banyak baris yang dikembalikan, sedangkan OFFSET menentukan berapa baris awal yang dilewati. Keduanya sering dipakai untuk halaman 1, 2, 3 pada tabel di aplikasi.

CARA MEMAKAI

Gunakan ORDER BY terlebih dahulu agar halaman memiliki urutan yang stabil. Misalnya 20 data per halaman: halaman 1 memakai OFFSET 0, halaman 2 OFFSET 20, halaman 3 OFFSET 40.

-- Halaman 1
ORDER BY id
LIMIT 20 OFFSET 0;

-- Halaman 3
ORDER BY id
LIMIT 20 OFFSET 40;

CONTOH PENGGUNAAN LENGKAP

Untuk halaman transaksi pada aplikasi, hitung offset dengan rumus (nomor_halaman - 1) × ukuran_halaman. Contoh halaman 4 dengan 25 baris per halaman berarti OFFSET 75.

SELECT id, nama, total, tanggal
FROM transaksi
WHERE status = 'LUNAS'
ORDER BY tanggal DESC, id DESC
LIMIT 25 OFFSET 75;

KEGUNAAN / MANFAAT

Mengurangi data yang dikirim ke aplikasi, membuat pagination, preview data, dashboard, API listing, dan pengambilan data bertahap.

PERHATIAN PADA DATA BESAR

OFFSET yang sangat besar dapat menjadi mahal karena database tetap perlu menemukan dan melewati banyak baris. Untuk dataset besar atau pagination berfrekuensi tinggi, pertimbangkan keyset/cursor pagination.

-- Contoh keyset pagination sederhana
SELECT id, nama, total
FROM transaksi
WHERE id < 1000
ORDER BY id DESC
LIMIT 20;

PERBEDAAN DIALECT

MySQL, PostgreSQL, dan SQLite mendukung LIMIT. SQL Server biasanya menggunakan TOP atau OFFSET ... FETCH. Oracle memiliki pendekatan seperti FETCH FIRST dan OFFSET pada versi modern. Selalu cek dialect database target.

CATATAN & ERROR UMUM

LIMIT tanpa ORDER BY tidak cocok untuk pagination yang membutuhkan urutan konsisten. OFFSET juga dapat menghasilkan halaman yang berubah jika data disisipkan/dihapus selama pengguna melakukan paging.

DIALECT NOTE Sintaks pembatas hasil berbeda antar DBMS. Konsepnya sama: tentukan urutan terlebih dahulu, lalu ambil subset hasil dengan mekanisme yang tersedia pada DBMS.

MODULE 03

AGGREGATE // GROUP

Merangkum banyak baris menjadi statistik atau kelompok data.

Q-05COUNT / SUM / AVGBEGINNER
SELECT
  COUNT(*) AS jumlah,
  SUM(total) AS omzet,
  AVG(total) AS rata_rata
FROM transaksi;

Menghitung baris, menjumlahkan nilai, dan mencari rata-rata.

FUNGSI / TUJUAN

Merangkum banyak baris menjadi angka statistik.

CARA MENGGUNAKAN

Pilih fungsi sesuai kebutuhan: COUNT untuk jumlah, SUM untuk total, AVG untuk rata-rata, MIN untuk nilai terkecil, MAX untuk terbesar. Tambahkan GROUP BY jika statistik perlu dibuat per kelompok.

SELECT COUNT(*) AS jumlah, SUM(total) AS omzet, AVG(total) AS rata_rata FROM transaksi;

KEGUNAAN / USE CASE

Dashboard, laporan penjualan, rekonsiliasi, statistik operasional, dan analisis performa.

CARA KERJA

COUNT(*) menghitung baris. COUNT(kolom) mengabaikan NULL pada kolom. SUM/AVG/MIN/MAX bekerja pada nilai yang sesuai tipe datanya.

CATATAN & ERROR UMUM

Jangan menganggap COUNT(kolom) sama dengan COUNT(*). NULL dapat membuat hasil agregasi berbeda dari perkiraan.

Q-06GROUP BYBEGINNER
SELECT kota, COUNT(*) AS jumlah
FROM pelanggan
GROUP BY kota;

Mengelompokkan baris berdasarkan satu atau lebih kolom sebelum agregasi.

FUNGSI / TUJUAN

Membagi baris menjadi kelompok lalu menjalankan agregasi pada setiap kelompok.

CARA MENGGUNAKAN

Tentukan kolom kategori pada GROUP BY dan agregat pada SELECT. Setiap kolom non-agregat di SELECT biasanya harus muncul di GROUP BY, tergantung aturan DBMS.

SELECT kota, COUNT(*) AS jumlah FROM pelanggan GROUP BY kota;

KEGUNAAN / USE CASE

Membuat laporan per kota, per produk, per bulan, per departemen, atau kategori lain.

CARA KERJA

GROUP BY mengubah kumpulan baris menjadi satu hasil per kombinasi kelompok. Agregat dihitung di dalam masing-masing kelompok.

CATATAN & ERROR UMUM

Kesalahan umum adalah memilih kolom biasa yang tidak ada di GROUP BY atau salah menempatkan kondisi agregat di WHERE.

Q-07HAVINGINTERMEDIATE
SELECT kota, SUM(total) omzet
FROM transaksi
GROUP BY kota
HAVING SUM(total) > 10000000;

Memfilter hasil setelah proses GROUP BY. Berbeda dengan WHERE yang memfilter baris sebelum agregasi.

FUNGSI / TUJUAN

Memfilter kelompok setelah proses GROUP BY dan agregasi selesai.

CARA MENGGUNAKAN

Gunakan WHERE untuk menyaring baris mentah sebelum grouping. Gunakan HAVING untuk menyaring hasil kelompok berdasarkan fungsi agregat.

SELECT kota, SUM(total) AS omzet FROM transaksi GROUP BY kota HAVING SUM(total) > 10000000;

KEGUNAAN / USE CASE

Mencari cabang dengan omzet tertentu, pelanggan dengan transaksi minimal, atau kategori yang memenuhi ambang statistik.

CARA KERJA

Urutan konsep: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. HAVING bekerja pada hasil kelompok.

CATATAN & ERROR UMUM

Jangan memakai HAVING untuk filter baris sederhana jika WHERE sudah cukup; WHERE biasanya dapat mengurangi data lebih awal.

Q-08INNER JOININTERMEDIATE
SELECT p.nama, t.total
FROM pelanggan p
INNER JOIN transaksi t
  ON t.pelanggan_id = p.id;

Hanya mengembalikan baris yang memiliki pasangan di kedua tabel.

FUNGSI / TUJUAN

Menggabungkan hanya baris yang memiliki pasangan pada kedua tabel.

CARA MENGGUNAKAN

Tentukan tabel utama, gunakan INNER JOIN, lalu tulis kondisi hubungan pada ON. Pastikan kolom join mewakili relasi yang benar, biasanya primary key ke foreign key.

SELECT p.nama, t.total FROM pelanggan p INNER JOIN transaksi t ON t.pelanggan_id = p.id;

KEGUNAAN / USE CASE

Mengambil data transaksi beserta nama pelanggan, data pegawai beserta departemen, atau informasi lintas tabel yang membutuhkan pasangan.

CARA KERJA

INNER JOIN membuang baris yang tidak menemukan pasangan. Alias p dan t membuat query lebih ringkas.

CATATAN & ERROR UMUM

JOIN tanpa kondisi yang benar dapat menghasilkan terlalu banyak baris. Periksa kardinalitas relasi 1:1, 1:N, atau N:N.

Q-09LEFT JOININTERMEDIATE
SELECT p.nama, t.total
FROM pelanggan p
LEFT JOIN transaksi t
  ON t.pelanggan_id = p.id;

Semua baris dari tabel kiri tetap muncul; data kanan menjadi NULL jika tidak ada pasangan.

USE CASE
Mencari pelanggan yang belum pernah bertransaksi.

FUNGSI / TUJUAN

Menggabungkan tabel sambil mempertahankan seluruh baris dari tabel kiri.

CARA MENGGUNAKAN

Letakkan tabel yang ingin dipertahankan di sebelah kiri LEFT JOIN. Kondisi hubungan berada di ON. Baris kanan yang tidak punya pasangan menghasilkan NULL.

SELECT p.nama, t.total FROM pelanggan p LEFT JOIN transaksi t ON t.pelanggan_id = p.id;

KEGUNAAN / USE CASE

Menemukan pelanggan tanpa transaksi, produk tanpa penjualan, atau master data yang belum memiliki detail.

CARA KERJA

LEFT JOIN = semua baris kiri + pasangan kanan. Jika tidak ada pasangan, kolom kanan bernilai NULL.

CATATAN & ERROR UMUM

Memindahkan filter kolom tabel kanan dari ON ke WHERE dapat mengubah efek LEFT JOIN menjadi seperti INNER JOIN.

Q-10FULL / CROSS / SELF JOINADVANCED
SELECT a.nama, b.nama
FROM pegawai a
JOIN pegawai b
  ON a.manager_id = b.id;

SELF JOIN menghubungkan tabel dengan dirinya sendiri. FULL/CROSS memiliki dukungan berbeda antar DBMS.

FUNGSI / TUJUAN

Menggunakan variasi JOIN untuk kebutuhan relasi khusus: self join, full outer join, dan cross join.

CARA MENGGUNAKAN

Self JOIN memakai alias berbeda untuk tabel yang sama. FULL OUTER JOIN mempertahankan sisi kiri dan kanan. CROSS JOIN menghasilkan kombinasi setiap baris dengan setiap baris.

SELECT a.nama AS pegawai, b.nama AS manager FROM pegawai a JOIN pegawai b ON a.manager_id = b.id;

KEGUNAAN / USE CASE

Struktur hierarki, pasangan data, rekonsiliasi dua sumber, dan kombinasi seluruh kemungkinan.

CARA KERJA

SELF JOIN perlu alias agar dua peran tabel dapat dibedakan. FULL/CROSS JOIN memiliki dukungan dan sintaks yang berbeda antar DBMS.

CATATAN & ERROR UMUM

CROSS JOIN dapat menghasilkan jumlah baris sangat besar. Selalu perkirakan kardinalitas sebelum menjalankannya pada tabel besar.

MODULE 05

DML // CHANGE DATA

Perintah untuk menambah, mengubah, dan menghapus data.

Q-11INSERTBEGINNER
INSERT INTO pelanggan (nama, kota)
VALUES ('Andi', 'Jakarta');

Menambahkan baris baru. Sebutkan nama kolom secara eksplisit agar query lebih aman terhadap perubahan struktur tabel.

FUNGSI / TUJUAN

Menambahkan satu atau lebih baris baru ke tabel.

CARA MENGGUNAKAN

Sebutkan kolom target secara eksplisit, lalu berikan VALUES dengan jumlah dan urutan nilai yang sesuai. Untuk banyak baris, gunakan beberapa VALUES jika didukung.

INSERT INTO pelanggan (nama, kota) VALUES ('Andi', 'Jakarta');

KEGUNAAN / USE CASE

Memasukkan pelanggan baru, transaksi baru, master data, atau hasil proses ETL.

CARA KERJA

INSERT INTO menentukan tabel dan kolom tujuan. VALUES menyediakan data. Kolom yang tidak disebutkan memakai default atau NULL jika diperbolehkan.

CATATAN & ERROR UMUM

Pastikan tipe data, constraint, primary key, foreign key, dan nilai NOT NULL terpenuhi. Hindari bergantung pada urutan kolom tabel.

Q-12UPDATEBEGINNER
UPDATE pelanggan
SET kota = 'Bandung'
WHERE id = 10;
RISIKO TINGGI: UPDATE tanpa WHERE dapat mengubah seluruh baris.

FUNGSI / TUJUAN

Mengubah nilai pada baris yang sudah ada.

CARA MENGGUNAKAN

Tulis tabel setelah UPDATE, kolom baru setelah SET, dan gunakan WHERE untuk menentukan target. Sebelum menjalankan perubahan besar, uji WHERE dengan SELECT terlebih dahulu.

UPDATE pelanggan SET kota = 'Bandung' WHERE id = 10;

KEGUNAAN / USE CASE

Koreksi data, perubahan status, pembaruan alamat, dan proses sinkronisasi data.

CARA KERJA

UPDATE mengubah baris yang memenuhi WHERE. Tanpa WHERE, semua baris dapat terkena perubahan.

CATATAN & ERROR UMUM

Risiko terbesar adalah WHERE terlalu luas atau hilang. Untuk perubahan penting gunakan transaksi dan validasi jumlah baris.

Q-13DELETEBEGINNER
DELETE FROM pelanggan
WHERE status = 'NONAKTIF';

Menghapus baris berdasarkan kondisi. Untuk mengosongkan seluruh tabel, TRUNCATE biasanya lebih sesuai, tetapi perilakunya bergantung DBMS.

FUNGSI / TUJUAN

Menghapus baris berdasarkan kondisi tertentu.

CARA MENGGUNAKAN

Gunakan DELETE FROM nama_tabel lalu WHERE. Uji kondisi dengan SELECT terlebih dahulu. Jika ingin mengosongkan seluruh tabel, pertimbangkan TRUNCATE sesuai kebutuhan DBMS.

DELETE FROM pelanggan WHERE status = 'NONAKTIF';

KEGUNAAN / USE CASE

Menghapus data yang memang tidak diperlukan, membersihkan data uji, atau menjalankan proses retensi data.

CARA KERJA

DELETE menghapus baris yang cocok. TRUNCATE umumnya mengosongkan tabel secara lebih menyeluruh dan memiliki aturan transaksi/identity yang berbeda antar DBMS.

CATATAN & ERROR UMUM

DELETE tanpa WHERE dapat menghapus seluruh isi tabel. Jangan mengandalkan undo aplikasi; gunakan backup/transaksi bila tersedia.

MODULE 06

DDL // STRUCTURE

DDL (Data Definition Language) digunakan untuk mendefinisikan, membuat, mengubah, dan menghapus struktur objek database seperti database, tabel, kolom, constraint, dan index.

Q-18CREATE TABLEBEGINNER
CREATE TABLE pelanggan (
  id INT PRIMARY KEY,
  nama VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE,
  dibuat_pada DATE DEFAULT CURRENT_DATE
);

Membuat tabel baru sekaligus menentukan nama kolom, tipe data, dan aturan (constraint) yang menjaga kualitas data.

FUNGSI / TUJUAN

CREATE TABLE membangun struktur penyimpanan data baru. Anda menentukan kolom apa yang tersedia, tipe data yang boleh masuk, serta aturan seperti PRIMARY KEY, NOT NULL, UNIQUE, DEFAULT, dan CHECK.

CARA MEMAKAI

Gunakan pola CREATE TABLE nama_tabel (kolom tipe_data constraint, ...). Tentukan primary key untuk identitas baris, NOT NULL untuk field wajib, UNIQUE untuk nilai yang tidak boleh duplikat, dan DEFAULT untuk nilai otomatis.

CREATE TABLE produk (
  id INT PRIMARY KEY,
  nama VARCHAR(100) NOT NULL,
  harga DECIMAL(12,2) CHECK (harga >= 0),
  stok INT DEFAULT 0
);

CONTOH PENGGUNAAN LENGKAP

Misalnya aplikasi penjualan membutuhkan tabel pelanggan. Buat struktur terlebih dahulu, lalu masukkan data dengan INSERT. Setelah tabel tersedia, query SELECT, UPDATE, DELETE, dan JOIN dapat digunakan terhadap tabel tersebut.

CREATE TABLE pelanggan (
  id INT PRIMARY KEY,
  nama VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE
);

INSERT INTO pelanggan (id, nama, email)
VALUES (1, 'Andi', 'andi@example.com');

SELECT * FROM pelanggan;

MANFAAT / USE CASE

Membangun fondasi database untuk aplikasi, membuat struktur data konsisten, mencegah data invalid melalui constraint, dan mendokumentasikan bentuk data yang diharapkan.

CARA KERJA

DBMS memvalidasi nama tabel dan kolom, membuat metadata struktur, lalu mendaftarkan constraint. Setelah berhasil, tabel menjadi objek database yang dapat diakses oleh query DML seperti INSERT, UPDATE, dan DELETE.

CATATAN & ERROR UMUM

Hindari nama kolom yang membingungkan atau reserved keyword. Pilih tipe data sesuai kebutuhan. PRIMARY KEY harus unik dan tidak NULL. Struktur constraint yang salah dapat menyulitkan perubahan skema di kemudian hari.

PERBEDAAN DBMS

Sintaks tipe data dan auto-increment berbeda antar DBMS. MySQL umum memakai AUTO_INCREMENT, PostgreSQL sering memakai GENERATED AS IDENTITY, SQL Server memakai IDENTITY, sedangkan SQLite memiliki aturan INTEGER PRIMARY KEY yang khas.

Q-19ALTER TABLEINTERMEDIATE
ALTER TABLE pelanggan
ADD COLUMN telepon VARCHAR(30);

ALTER TABLE pelanggan
ADD COLUMN aktif BOOLEAN DEFAULT TRUE;

Mengubah struktur tabel yang sudah ada tanpa harus membuat ulang seluruh tabel dari awal.

FUNGSI / TUJUAN

ALTER TABLE digunakan ketika kebutuhan struktur berubah, misalnya menambah kolom, mengubah definisi kolom, mengganti nama kolom/tabel, atau menambah maupun menghapus constraint.

CARA MEMAKAI

Pola paling umum adalah ALTER TABLE nama_tabel ADD COLUMN nama_kolom tipe_data. Operasi lain seperti RENAME, DROP COLUMN, atau perubahan tipe data memiliki sintaks yang berbeda antar DBMS.

ALTER TABLE pelanggan ADD COLUMN telepon VARCHAR(30);
ALTER TABLE pelanggan RENAME COLUMN nama TO nama_lengkap;

CONTOH PENGGUNAAN LENGKAP

Bayangkan aplikasi awalnya hanya menyimpan nama dan email. Ketika fitur komunikasi ditambahkan, kolom telepon diperlukan. Tambahkan kolom, isi data yang tersedia, lalu validasi hasilnya.

ALTER TABLE pelanggan
ADD COLUMN telepon VARCHAR(30);

UPDATE pelanggan
SET telepon = '08123456789'
WHERE id = 1;

SELECT id, nama, telepon
FROM pelanggan;

MANFAAT / USE CASE

Memungkinkan evolusi schema ketika aplikasi berkembang, menambahkan atribut baru, memperbaiki nama kolom, dan menyesuaikan database dengan kebutuhan bisnis tanpa membuat tabel baru dari nol.

CARA KERJA & RISIKO

DBMS mengubah metadata dan, tergantung jenis perubahan serta DBMS, dapat melakukan migrasi atau penulisan ulang data. Pada tabel besar, ALTER tertentu dapat membutuhkan waktu lama atau lock sehingga sebaiknya direncanakan saat beban rendah.

CATATAN & ERROR UMUM

Jangan langsung menambahkan NOT NULL pada kolom baru jika baris lama belum memiliki nilai yang valid. Uji perubahan pada staging, siapkan backup, dan periksa dampaknya terhadap aplikasi, view, trigger, index, serta query yang sudah ada.

PERBEDAAN DBMS

ADD COLUMN relatif umum, tetapi MODIFY/ALTER COLUMN, RENAME, dan perubahan tipe data berbeda antara MySQL, PostgreSQL, SQL Server, dan SQLite. Selalu cek sintaks DBMS yang digunakan sebelum deployment.

Q-20DROP / TRUNCATE TABLEADVANCED
TRUNCATE TABLE pelanggan;

DROP TABLE pelanggan;

TRUNCATE mengosongkan data tabel, sedangkan DROP menghapus objek tabel beserta strukturnya. Keduanya harus dipakai dengan sangat hati-hati.

FUNGSI / TUJUAN

TRUNCATE TABLE dipakai untuk mengosongkan seluruh baris tabel secara cepat. DROP TABLE menghapus tabel sebagai objek database sehingga struktur, data, dan objek terkait dapat ikut hilang sesuai aturan DBMS.

CARA MEMAKAI

Gunakan TRUNCATE ketika struktur tabel masih dibutuhkan tetapi seluruh data perlu dikosongkan. Gunakan DROP hanya ketika tabel memang tidak lagi diperlukan.

-- Kosongkan isi, pertahankan struktur
TRUNCATE TABLE pelanggan;

-- Hapus tabel dan strukturnya
DROP TABLE pelanggan;

CONTOH PENGGUNAAN LENGKAP

Dalam lingkungan development, tabel staging dapat dikosongkan sebelum proses import ulang. Jika sebuah tabel percobaan sudah tidak digunakan, tabel tersebut dapat dihapus setelah dependensi diperiksa.

-- Development / staging: kosongkan data staging
TRUNCATE TABLE staging_transaksi;

-- Hapus tabel sementara setelah tidak diperlukan
DROP TABLE IF EXISTS temp_import;

MANFAAT / USE CASE

TRUNCATE berguna untuk reset tabel staging, testing, dan proses reload data. DROP berguna untuk membersihkan tabel sementara, melakukan perubahan desain besar, atau menghapus objek yang sudah obsolete.

PERBEDAAN TRUNCATE vs DELETE vs DROP

DELETE menghapus baris dan dapat memakai WHERE. TRUNCATE mengosongkan seluruh tabel tanpa WHERE dan biasanya lebih efisien untuk reset penuh. DROP menghapus tabelnya, bukan hanya datanya. Jangan menyamakan ketiganya.

⚠ CATATAN KESELAMATAN

Periksa koneksi database, nama schema, backup, foreign key, dependency, permission, dan environment sebelum menjalankan operasi destruktif. Jangan menjalankan DROP/TRUNCATE di production tanpa prosedur perubahan yang jelas. Dukungan rollback dan perilaku transaksi dapat berbeda antar DBMS.

DBMS & DEPENDENCY

Perilaku TRUNCATE, cascade, identity reset, foreign key, trigger, dan transactional DDL berbeda antar DBMS. PostgreSQL misalnya menyediakan opsi seperti RESTART IDENTITY/CASCADE, sedangkan implementasi DBMS lain memiliki aturan tersendiri.

⚠ DDL & SCHEMA SAFETY
Perubahan struktur database dapat memengaruhi aplikasi, query, view, index, foreign key, dan proses ETL. Uji perubahan pada environment non-production, pastikan backup dan migration plan tersedia, lalu verifikasi hasilnya setelah deployment.

MODULE 07

LOGIC // FUNCTIONS

Logika kondisional, penanganan NULL, dan fungsi transformasi yang sering dipakai dalam query.

Q-14CASE WHENINTERMEDIATE
SELECT nama,
CASE
  WHEN total >= 10000000 THEN 'VIP'
  WHEN total >= 5000000 THEN 'GOLD'
  ELSE 'REGULAR'
END AS level_pelanggan
FROM pelanggan;

Membuat logika IF/ELSE di dalam SQL untuk klasifikasi atau transformasi.

FUNGSI / TUJUAN

Membuat logika kondisi IF/ELSE di dalam query dan menghasilkan nilai berdasarkan kondisi.

CARA MENGGUNAKAN

Gunakan CASE WHEN kondisi THEN hasil. Tambahkan WHEN sebanyak diperlukan dan ELSE sebagai nilai cadangan. Tutup dengan END dan beri alias.

SELECT nama, CASE WHEN total >= 10000000 THEN 'VIP' WHEN total >= 5000000 THEN 'GOLD' ELSE 'REGULAR' END AS level_pelanggan FROM pelanggan;

KEGUNAAN / USE CASE

Klasifikasi pelanggan, status transaksi, kategori umur, label laporan, dan transformasi nilai.

CARA KERJA

CASE dievaluasi dari kondisi WHEN secara berurutan. Pada simple CASE, ekspresi dibandingkan dengan beberapa nilai; searched CASE memakai kondisi lengkap.

CATATAN & ERROR UMUM

Perhatikan urutan kondisi. Kondisi yang lebih umum di atas dapat menangkap baris sebelum kondisi yang lebih spesifik.

Q-15NULL HANDLINGINTERMEDIATE
SELECT nama,
  COALESCE(telepon, 'Tidak tersedia')
FROM pelanggan
WHERE email IS NOT NULL;

COALESCE memilih nilai non-NULL pertama. Gunakan IS NULL / IS NOT NULL untuk pengujian NULL.

FUNGSI / TUJUAN

Menangani nilai NULL dan menyediakan nilai pengganti ketika data kosong.

CARA MENGGUNAKAN

Gunakan IS NULL/IS NOT NULL untuk pengujian. Gunakan COALESCE(a,b,c) untuk mengambil nilai non-NULL pertama.

SELECT nama, COALESCE(telepon, 'Tidak tersedia') FROM pelanggan WHERE email IS NOT NULL;

KEGUNAAN / USE CASE

Membuat laporan yang tidak menampilkan NULL mentah, fallback data, dan logika yang aman terhadap data kosong.

CARA KERJA

NULL berarti nilai tidak diketahui/tidak tersedia, bukan nol dan bukan string kosong. Operasi dengan NULL mengikuti aturan three-valued logic.

CATATAN & ERROR UMUM

Jangan gunakan = NULL atau <> NULL. Gunakan IS NULL/IS NOT NULL. Perhatikan perbedaan COALESCE dan fungsi pengganti khusus DBMS seperti IFNULL.

Q-16STRING FUNCTIONSINTERMEDIATE
SELECT
  UPPER(nama),
  TRIM(email)
FROM pelanggan;

Fungsi teks seperti UPPER, LOWER, TRIM, REPLACE, CONCAT tersedia dengan variasi sintaks antar DBMS.

FUNGSI / TUJUAN

Membersihkan, mengubah, dan menggabungkan teks dalam query.

CARA MENGGUNAKAN

Gunakan UPPER/LOWER untuk normalisasi huruf, TRIM untuk spasi, REPLACE untuk mengganti bagian teks, dan CONCAT untuk menggabungkan nilai. Cek fungsi yang tersedia pada DBMS.

SELECT UPPER(nama) AS nama_besar, TRIM(email) AS email_bersih FROM pelanggan;

KEGUNAAN / USE CASE

Pembersihan data, pencarian yang konsisten, pembentukan label, ekspor laporan, dan normalisasi data teks.

CARA KERJA

Fungsi string menerima kolom atau ekspresi dan menghasilkan teks baru tanpa mengubah nilai asli kecuali dipakai dalam UPDATE.

CATATAN & ERROR UMUM

Sintaks CONCAT, operator concatenation, dan perilaku NULL berbeda antar DBMS. Uji query pada database target.

Q-17DATE / TIMEINTERMEDIATE
SELECT id, tanggal,
  EXTRACT(YEAR FROM tanggal) AS tahun
FROM transaksi;

Untuk filter periode, grouping bulanan, umur data, dan perhitungan tanggal. Fungsi tanggal sangat bergantung dialect.

FUNGSI / TUJUAN

Mengolah tanggal dan waktu untuk filter periode, pengelompokan, dan analisis waktu.

CARA MENGGUNAKAN

Gunakan fungsi tanggal sesuai DBMS. EXTRACT mengambil bagian seperti YEAR/MONTH. Untuk filter periode, lebih aman gunakan batas tanggal yang jelas daripada mengubah kolom dengan fungsi jika ingin index tetap efektif.

SELECT id, tanggal, EXTRACT(YEAR FROM tanggal) AS tahun FROM transaksi;

KEGUNAAN / USE CASE

Laporan bulanan/tahunan, aging, SLA, tren waktu, periode pajak, dan analisis transaksi.

CARA KERJA

Tanggal memiliki komponen tahun/bulan/hari dan waktu dapat memiliki jam/menit/detik. Fungsi seperti DATEADD, DATEDIFF, DATE_TRUNC, dan INTERVAL berbeda antar DBMS.

CATATAN & ERROR UMUM

Perhatikan timezone, format tanggal, inclusive/exclusive boundary, dan fungsi yang membuat index sulit digunakan.

MODULE 08

SUBQUERY // CTE

Membangun query bertingkat dan query modular. Subquery membantu membuat kondisi berdasarkan hasil query lain, sedangkan CTE memberi nama pada hasil sementara agar query kompleks lebih mudah dibaca, diuji, dan dikembangkan.

Q-19SUBQUERYINTERMEDIATE
SELECT nama, total
FROM transaksi
WHERE total > (
  SELECT AVG(total)
  FROM transaksi
);

Menjalankan query di dalam query lain untuk menghasilkan nilai atau himpunan yang dipakai oleh query utama.

FUNGSI / TUJUAN

Subquery digunakan ketika keputusan query utama bergantung pada hasil query lain. Contoh paling mudah adalah mencari transaksi yang nilainya lebih besar dari rata-rata seluruh transaksi.

CARA MEMAKAI

Tempatkan subquery di dalam tanda kurung. Subquery dapat menghasilkan satu nilai, banyak nilai, atau digunakan untuk menguji keberadaan baris melalui EXISTS.

-- Scalar subquery: menghasilkan satu nilai
SELECT *
FROM transaksi
WHERE total > (SELECT AVG(total) FROM transaksi);

CONTOH IN / EXISTS

Gunakan IN ketika hasil subquery berupa daftar nilai. Gunakan EXISTS ketika fokusnya adalah apakah minimal satu baris yang cocok tersedia.

-- IN
SELECT * FROM pelanggan
WHERE id IN (
  SELECT pelanggan_id FROM transaksi
);

-- EXISTS
SELECT p.*
FROM pelanggan p
WHERE EXISTS (
  SELECT 1 FROM transaksi t
  WHERE t.pelanggan_id = p.id
);

KEGUNAAN / MANFAAT

Membuat filter berdasarkan statistik, mencari data yang memiliki/tidak memiliki relasi, membandingkan nilai dengan agregat, dan menyusun logika yang tidak praktis jika ditulis sebagai satu kondisi sederhana.

CARA KERJA

Database mengevaluasi subquery sesuai konteksnya. Pada correlated subquery, subquery dapat dievaluasi berdasarkan setiap baris query luar. Optimizer dapat mengubah strategi eksekusi, sehingga jangan berasumsi bahwa bentuk SQL selalu sama dengan rencana eksekusi.

CATATAN & ERROR UMUM

Scalar subquery harus menghasilkan satu nilai; jika menghasilkan banyak baris, operator yang digunakan harus sesuai. Perhatikan NULL saat menggunakan NOT IN karena three-valued logic dapat menghasilkan hasil yang mengejutkan.

Q-20CTE / WITHINTERMEDIATE
WITH omzet AS (
  SELECT pelanggan_id, SUM(total) AS total_omzet
  FROM transaksi
  GROUP BY pelanggan_id
)
SELECT *
FROM omzet
WHERE total_omzet > 10000000;

CTE memberi nama pada hasil query sementara sehingga langkah analisis dapat dipisahkan menjadi blok yang jelas.

FUNGSI / TUJUAN

WITH membuat Common Table Expression (CTE). CTE sangat berguna untuk memecah query panjang menjadi beberapa tahap bernama seperti omzet, pelanggan_aktif, atau ranking.

CARA MEMAKAI

Mulai dengan WITH, beri nama CTE, tulis query di dalam kurung, lalu gunakan nama CTE pada query utama. Anda dapat memiliki lebih dari satu CTE dan menghubungkannya satu sama lain.

WITH penjualan AS (...),
pelanggan_aktif AS (...)
SELECT ...
FROM penjualan
JOIN pelanggan_aktif ...;

CONTOH PENGGUNAAN LENGKAP

Misalnya ingin mencari pelanggan dengan omzet di atas rata-rata omzet pelanggan. Buat ringkasan omzet per pelanggan terlebih dahulu, kemudian hitung rata-ratanya di tahap berikutnya.

WITH omzet AS (
  SELECT pelanggan_id, SUM(total) AS omzet
  FROM transaksi
  GROUP BY pelanggan_id
), rata AS (
  SELECT AVG(omzet) AS avg_omzet
  FROM omzet
)
SELECT o.pelanggan_id, o.omzet
FROM omzet o
CROSS JOIN rata r
WHERE o.omzet > r.avg_omzet;

KEGUNAAN / MANFAAT

Meningkatkan keterbacaan query, memudahkan debugging, menghindari pengulangan subquery yang sama dalam kode, dan cocok untuk pipeline analisis bertahap. CTE recursive juga dapat digunakan untuk struktur hierarki pada DBMS yang mendukungnya.

CTE VS SUBQUERY

Subquery cocok untuk logika kecil dan lokal. CTE lebih nyaman ketika hasil antara perlu diberi nama, dipakai ulang dalam query, atau query memiliki beberapa tahap analisis. CTE bukan otomatis berarti lebih cepat; performa tetap bergantung pada optimizer dan DBMS.

CATATAN & ERROR UMUM

Pastikan setiap CTE memiliki nama unik dan kolom yang jelas. Jangan menganggap CTE selalu menjadi tabel fisik atau selalu dimaterialisasi; perilakunya bergantung pada DBMS dan execution plan.

MODULE 09

WINDOW // ANALYTICS

Window function menghitung nilai berdasarkan kumpulan baris yang berhubungan dengan baris saat ini tanpa menggabungkan hasil menjadi satu baris seperti GROUP BY. Ini adalah fondasi ranking, running total, perbandingan periode, dan analisis tren.

Q-21ROW_NUMBER / RANK / OVERADVANCED
SELECT
  nama, kota, total,
  ROW_NUMBER() OVER (
    PARTITION BY kota
    ORDER BY total DESC
  ) AS ranking
FROM transaksi;

Membuat ranking dan analitik antarbaris sambil tetap mempertahankan detail setiap transaksi.

FUNGSI / TUJUAN

Window function memungkinkan kita menghitung sesuatu berdasarkan baris lain yang masih berada dalam satu window, tanpa mengurangi jumlah baris hasil. Berbeda dengan GROUP BY yang merangkum beberapa baris menjadi satu baris per grup.

KOMPONEN OVER

PARTITION BY membagi data menjadi kelompok analisis. ORDER BY menentukan urutan di dalam kelompok. Beberapa fungsi juga dapat memakai frame untuk menentukan rentang baris yang dihitung.

ROW_NUMBER() OVER (
  PARTITION BY kota
  ORDER BY total DESC
)

CONTOH RANKING

Untuk mencari 3 transaksi terbesar pada setiap kota, buat ranking per kota lalu filter ranking tersebut pada query luar.

WITH ranked AS (
  SELECT nama, kota, total,
    ROW_NUMBER() OVER (
      PARTITION BY kota
      ORDER BY total DESC, id DESC
    ) AS rn
  FROM transaksi
)
SELECT * FROM ranked
WHERE rn <= 3;

ROW_NUMBER VS RANK VS DENSE_RANK

ROW_NUMBER memberi nomor unik. RANK memberi peringkat yang sama untuk nilai sama dan dapat membuat celah peringkat. DENSE_RANK juga berbagi peringkat tetapi tidak membuat celah.

-- Nilai: 100, 100, 90
-- ROW_NUMBER : 1, 2, 3
-- RANK       : 1, 1, 3
-- DENSE_RANK : 1, 1, 2

LAG / LEAD & RUNNING TOTAL

LAG membaca baris sebelumnya, LEAD membaca baris berikutnya. Window aggregate seperti SUM dapat dipakai untuk running total dengan frame yang sesuai.

SELECT tanggal, total,
  LAG(total) OVER (ORDER BY tanggal) AS sebelumnya,
  SUM(total) OVER (
    ORDER BY tanggal
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total
FROM transaksi;

KEGUNAAN / MANFAAT

Ranking produk, top-N per kategori, running total, pertumbuhan periode, perbandingan transaksi sebelumnya, deteksi perubahan, analisis performa, dan laporan operasional yang tetap membutuhkan detail tiap baris.

CARA KERJA & KINERJA

Database menentukan partition dan urutan window, lalu menghitung fungsi untuk setiap baris. Window yang memerlukan sorting dapat mahal pada dataset besar. Filter hasil window biasanya dilakukan pada query luar atau CTE karena alias window tidak selalu dapat digunakan langsung di WHERE pada query yang sama.

CATATAN & ERROR UMUM

Pastikan ORDER BY memiliki tie-breaker jika hasil harus deterministik. Jangan tertukar antara GROUP BY dan window function. Perhatikan frame default dan perbedaan dukungan fungsi antar DBMS.

MODULE 10

TRANSACTION // SAFETY

Transaction mengelompokkan beberapa perubahan data menjadi satu unit kerja. Tujuannya adalah menjaga agar operasi yang saling bergantung berhasil seluruhnya atau dibatalkan seluruhnya sesuai kebutuhan.

BEGIN / START→INSERT / UPDATE / DELETE→VALIDATE→COMMITorROLLBACK
Q-22BEGIN / COMMIT / ROLLBACKADVANCED
BEGIN;

UPDATE saldo
SET jumlah = jumlah - 500000
WHERE rekening_id = 101;

UPDATE saldo
SET jumlah = jumlah + 500000
WHERE rekening_id = 202;

COMMIT;

Menjamin dua perubahan yang saling berkaitan diproses sebagai satu unit transaksi.

FUNGSI / TUJUAN

Transaction menjaga konsistensi saat beberapa INSERT, UPDATE, atau DELETE harus dianggap sebagai satu pekerjaan. Jika semua langkah berhasil, COMMIT membuat perubahan permanen. Jika terjadi masalah sebelum commit, ROLLBACK dapat membatalkan perubahan yang masih berada dalam transaksi.

CARA MEMAKAI

Pola umum adalah mulai transaction, lakukan perubahan, validasi hasil, lalu COMMIT jika benar. Jika validasi gagal atau terjadi error yang harus dibatalkan, gunakan ROLLBACK. Detail autocommit dan cara memulai transaksi berbeda antar driver/DBMS.

BEGIN;
UPDATE akun SET saldo = saldo - 500000 WHERE id = 101;
UPDATE akun SET saldo = saldo + 500000 WHERE id = 202;
COMMIT;

CONTOH PENGGUNAAN LENGKAP

Pada transfer dana, pengurangan saldo rekening A dan penambahan saldo rekening B tidak boleh hanya salah satunya yang tersimpan. Transaction memungkinkan aplikasi membatalkan seluruh operasi jika salah satu langkah gagal.

BEGIN;

UPDATE akun
SET saldo = saldo - 500000
WHERE id = 101 AND saldo >= 500000;

-- Aplikasi memeriksa row count / kondisi bisnis

UPDATE akun
SET saldo = saldo + 500000
WHERE id = 202;

COMMIT;

ROLLBACK DAN SAVEPOINT

ROLLBACK membatalkan perubahan transaksi yang belum di-commit. SAVEPOINT dapat menjadi titik pemulihan di tengah transaksi pada DBMS yang mendukungnya.

BEGIN;
UPDATE ...;
SAVEPOINT tahap_1;
UPDATE ...;
ROLLBACK TO tahap_1;
COMMIT;

ACID

Atomicity: unit kerja diperlakukan utuh. Consistency: aturan integritas tetap terpenuhi. Isolation: transaksi bersamaan diatur agar interaksinya sesuai isolation level. Durability: setelah commit, perubahan dirancang untuk bertahan sesuai jaminan sistem penyimpanan.

KEGUNAAN / MANFAAT

Pembayaran, transfer, pemrosesan invoice, stok, posting jurnal, batch update, sinkronisasi data, dan proses lain yang terdiri dari beberapa perubahan yang harus konsisten.

ISOLATION LEVEL

Isolation level mengatur bagaimana transaksi melihat perubahan transaksi lain. Konsep seperti READ COMMITTED, REPEATABLE READ, dan SERIALIZABLE memiliki trade-off antara konsistensi dan concurrency. Dukungan dan perilaku detail berbeda antar DBMS.

CATATAN & ERROR UMUM

Jangan membiarkan transaction terbuka terlalu lama karena dapat menahan lock atau sumber daya. Tangani error di aplikasi dan pastikan koneksi tidak meninggalkan transaction yang tidak jelas. Jangan menganggap COMMIT/ROLLBACK identik pada semua engine atau driver.
